# Матрица блокировок и обходов

Это инженерная карта, а не утверждение, что каждый метод применяется везде и всегда. Поведение зависит от провайдера, региона, времени и конкретной сети. Диагностика показывает симптомы; атрибуция «РКН/ТСПУ» требует дополнительных данных.

| Класс | Симптомы | Что проверять | Возможный обход | Ограничения | Статус в MVP |
|---|---|---|---|---|---|
| DNS: подмена, NXDOMAIN, redirect на blockpage | Домен резолвится в «не тот» IP, блок-страница, NXDOMAIN | Сравнить system DNS и DoH; проверить сертификат на полученном IP | DoH/DoT, свой resolver, подключение к доверенному IP | DoH тоже могут блокировать; CDN даёт разные валидные ответы; fallback может вернуть цензурированный ответ | DoH + system fallback, probe DNS |
| HTTP Host / blockpage | HTTP-запрос к домену даёт блок-страницу или redirect | `bbb probe --no-tls --port 80`, сравнить Host/IP | Дробление Host, иной Host/CDN, HTTPS, туннель | Ломаются наборы правил, которые собирают поток; HTTP без TLS небезопасен | `http-host-split`, `http-header-case` |
| TLS SNI / ClientHello | Таймаут или RST после ClientHello; домен виден в SNI | Probe TLS direct vs split; смотреть TTFB и стадию сброса | TLS record split внутри SNI, TCP segmentation, ECH (если доступен), туннель | Stateful DPI может собирать записи/поток; ECH могут блокировать отдельно | `tls-record-sni`, `tls-record-mid`, `tcp-sni` |
| TLS fingerprint / расширения | Блок не по домену, а по форме ClientHello, ALPN, ECH, GREASE | Сравнить разные клиенты/стратегии; проверить наличие ECH | Менять профиль клиента, отключать проблемное расширение, туннель | В MVP нет управления TLS fingerprint браузера; нельзя ломать безопасность | Частично: только фрагментация |
| IP / подсеть / CDN | Блок по адресу, а не по имени; несколько сайтов на одном IP падают вместе | TCP connect к IP, сравнить разные IP/CDN, traceroute | Доступный туннель, иной endpoint/CDN, смена маршрута | Фрагментация TLS не помогает, если IP заблокирован на L3 | SOCKS5 upstream |
| QUIC / HTTP/3 / UDP | HTTP/3 не работает, TCP/TLS работает; UDP 443 drops | Отдельный UDP/QUIC probe, сравнить с TCP | Заставить клиента использовать TCP/TLS, туннель с UDP, QUIC-aware desync | В MVP нет UDP proxy; браузер может сам пробовать HTTP/3 | Не реализовано; рекомендуется TCP fallback |
| Throttling / «16 KB curtain» | Страница начинает грузиться и зависает; большие ответы обрываются | Скачать объект > 64 KB, измерить байты до стопа, повторить по протоколам | Туннель, иной endpoint/CDN,transport-level обход | Если лимит по IP/сети, смена TLS-записи не поможет | Probe может показать объём ответа; полноценноготеста пока нет |
| Блокировка VPN-протоколов | WireGuard/OpenVPN/IPsec не поднимаются или быстро умирают | Проверить handshake, разные порты/транспорты | Обфусцированный туннель, TCP/443, маскировка под обычный TLS | Нужен рабочий сервер и протокол; активное зондирование может раскрыть туннель | Только подключение к уже существующему SOCKS5 |
| Active probing censor | Сервер работает, но после проверки censor блокирует IP/порт | Логи сервера, повторные подключения с разных сетей | Туннели с защитой от probing, аутентификация до ответа | Нельзя проверить только клиентским probe | Нет |
| Whitelist / mobile shutdown | Доступны только разрешённые сервисы, остальное drop | Проверить несколько независимых доменов/портов, сравнить Wi-Fi/mobile | Только заранее доступный разрешённый канал/туннель; иногда ничего | Если все внешние маршруты закрыты, локальный desync бессилен | Диагностика покажет массовый отказ; обход не гарантирован |
| BGP/routing/physical outage | Недоступны многие сети, высокие потери, нет маршрута | traceroute, looking glass, несколько провайдеров | Другой физический канал/провайдер, спутник, заранее поднятый туннель | Программный обход не создаёт физический маршрут | Нет |
| TLS MITM с доверенным корневым сертификатом | Сертификат «валиден», но выдан локальным центром | Проверить chain, pinning, сравнить с DoH/другой сетью | Не доверять локальному корню, pinning, туннель | Если корень установлен в ОС/браузер, обычная проверка TLS не спасает | Probe использует системное хранилище; отдельного pinning нет |
| Блокировка на стороне сервиса | Geo-block, санкционный отказ, аккаунт/бот-проверка | HTTP 403/451, страница сервиса, другой регион | Это не сетевая цензура; нужен легальный доступ/аккаунт | Антицензурный прокси не должен подменять личность или обходить auth | Не цель проекта |

## Практический порядок действий

1. `bbb doctor` — окружение и конфиг.
2. `bbb probe <host>` — DNS/TCP/TLS и стратегии.
3. Если `direct` работает, не включайте агрессивные методы.
4. Если ломается только TLS handshake, пробуйте `tls-record-sni`, затем `tcp-sni`.
5. Если TCP к IP не устанавливается, переходите к туннелю/другому endpoint.
6. Если не работает почти всё, проверяйте whitelist/отключение сети, а не крутите TTL.
7. Сохраняйте JSON-отчёты и сравнивайте сети/время. Не публикуйте отчёты с чувствительными доменами без редактуры.
